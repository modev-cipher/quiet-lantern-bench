## Fixes (feat/r2-voice)

1. **Channel abrupt-loss recycle** (gemini.rs): a socket that ends without
   goAway recycles like a goAway — `Renewing{None}` (sends refused
   retryably), bounded redial `[0, 500 ms, 2 s]` on the session's own key,
   `Reconnected`; `Expired` only when redial fails. Crash-loop guard (>2
   consecutive sub-5 s lives) and a `closing` flag (client close never
   recycles).
2. **Actor transcribe re-dial ladder** (voice_session.rs): every stream
   death signal (Error/Expired/closed/stall watchdog) starts a bounded
   re-dial `[500 ms, 3 s, 10 s]` through an injected dialer (production:
   `build_transcribe_channel`, fresh key rotation). The
   `transcribe_stream_lost` banner fires **only after exhaustion**; dialog
   transcription serves bubbles during the window.
3. **Per-utterance per-leg accounting + lost-turn recovery**
   (voice_session.rs): every mic chunk offered/delivered is counted per leg;
   the account re-bases at each mic VAD speech onset (silence dilution
   guard). A stream final whose dialog delivery fell below half re-delivers
   the final's text to the dialog model via `send_text` — parked through
   renewals (rides after the recap), honest `voice_turn_lost` UI event when
   truly undeliverable. **Audio loss is impossible to silence.**
4. **Soft capture gate** (voice_session.rs + voiceHalfDuplex.ts + lib.rs):
   the frontend AUTO gate now calls `voice_session_gate`/`ungate` — capture
   flows into a bounded 5 s ring (3 s pre-review) (zero egress while gated, VAD barge-in
   suppressed), and the release flushes the trailing idle-captured run
   (output plane idle = echo-free) to both legs: the release-window words
   survive. User privacy mutes and narration (webview playback the backend
   cannot see; including a mid-gate upgrade) stay hard zero-capture.
